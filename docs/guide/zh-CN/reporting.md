# 使用统计上报

> 本文是 [TeamAI CLI 使用指南](../../usage-guide.zh-CN.md) 的一部分。

---

`teamai pull` 默认把会话和使用次数提交进团队仓库，`teamai workflow` 也会提交[运行记录](workflow.md#运行记录)。不想要这些提交时：

```yaml
# teamai.yaml
usageReport: false
```

本机覆盖写在该 scope 的 `config.yaml`：

```yaml
usageReportEnabled: false
```

`teamai doctor` 会说明当前开没开、设置来自哪里。

自动上报未确认成功时，数据会留在本地。`teamai status` 会显示
`auto-report: pending since <time>`，并提示运行 `teamai pull --verbose`
重试、查看原因。重复失败保留首次时间；上报成功，或关闭上报后再次 pull，
都会清除提示。关闭上报会保留本地数据。仅保留了使用记录并不表示上报失败。

### 按运行模式统计你的会话

这些计数只包括你自己的会话。teamai 自己启动的会话（如工作流步骤或评审）不计入任何一项；你的会话被某个步骤继续后，只计到该步骤之前。你的工具为 skill 驱动的运行启动的会话（如子代理或 worktree 任务）仍算作你的：只有它的 worktree 或 `teamai/<run>/…` 分支能看出它的来历。

每个会话会记录它的[运行模式](workflow.md#有人值守与无人值守的运行)，`stats/<member>.yaml` 按模式拆分计数：

```yaml
prompts: 430          # 你自己会话的全部 prompt
attended:
  prompts: 395        # 记录为有人值守
unattended:
  prompts: 3          # 记录为无人值守，例如你的 hook 在 CI 中
```

`interventions`、`prompts`、`tokens` 和 `daily` 同理。两种模式都不包含的部分（这里是 32 个 prompt）记录时没有模式：包括 teamai 记录模式之前上报的计数，以及升级 teamai 后没有再记录任何事件的会话。一个会话自上次上报以来新增的轮次，按它最新一条事件的模式计入。`teamai digest` 和仪表盘把它显示为 `not recorded`。

### 你的会话产出了什么

你的一个会话空闲 6 小时后，下一次上报会把它计入 `outcomes`，按它的运行模式和它的产出分行。无人值守的会话还会由结束其任务的 `teamai score --drain` 计入，因此临时运行器也会上报它的会话：

```yaml
outcomes:
  attended:
    pr:       { sessions: 12, tokens: { input: …, output: … }, interventions: 73 }
    learning: { sessions: 5, tokens: { input: …, output: … }, interventions: 15 }
    none:     { sessions: 31, tokens: { input: …, output: … }, interventions: 68 }
  unattended:
    pr:       { sessions: 20, tokens: { input: …, output: … }, interventions: 8 }
  notRecorded:
    none:     { sessions: 7, tokens: { input: …, output: … }, interventions: 13 }
```

| 产出 | 会话产出了什么 |
|---|---|
| `commit` | 在会话所在检出中、从会话开始到最后一次 Stop 之间，以你的 git 身份提交的 commit |
| `pr` | 会话 Stop 时所在的最后一个分支上包含其中某个 commit、在某次上报查询时处于打开状态的拉取请求。在分离 HEAD 上的 Stop（例如变基过程中）沿用之前的分支。每次上报都会查询，直到找到为止，因此会话结束前已合并的拉取请求也会计入。使用 `deliver: pr` 所用的凭据；查询失败则不计入 |
| `learning` | `teamai contribute` 为该会话记录的经验（`--session-id`，否则为智能体当前会话） |
| `none` | 以上都没有 |

一个既有拉取请求又有经验的会话会同时出现在两行，因此各行不能相加。每个会话只计入一次：与其他上报基线同目录的 `reported-outcomes.json` 会标记它。升级到带有会话成果的版本后，你的第一次上报不计入任何已经结束的会话，因为记录它们的旧版本没有保存它们的 commit 和经验。上报只发布计数；会话 ID、commit 哈希、拉取请求 URL 和经验 ID 只保存在本机的仪表盘事件中。

以下情况记一次技能使用：agent 调用技能工具，读取某个技能的 `SKILL.md`，或者提示词点名技能：提示词开头的 `/code-review`，Codex 中的 `$code-review`，Pi 中的 `/skill:code-review`。只统计该工具已安装的技能，每个技能在一次提示中只记一次。`/Volumes/External/project` 这样的路径和 URL 中的路径段不算技能调用。已经记录的使用数据保持不变。
