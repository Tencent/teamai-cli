## Overview

Transform TeamAI from a simple skill-sharing CLI into a **Team Intelligence Platform** — every AI coding session contributes to shared knowledge (especially AI tool misuse patterns), every skill has usage metrics, and the system actively helps people discover valuable tools.

## Engineering Decisions (from /plan-eng-review)

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| 1 | Session data collection | Collect-then-summarize | The Stop hook does not call an LLM directly, avoiding recursion and per-session token cost |
| 2 | Skill usage tracking | PostToolUse hook + JSONL | Tracks Claude Code Skill tool calls; JSONL avoids concurrent-write races |
| 3 | Session storage format | Monthly aggregated MD files | Balances file count and readability; a 10-person team over 90 days ≈ 30 files |
| 4 | Hook injection | Extend the existing hooks.ts | Smallest diff, reuses the existing pattern |
| 5 | Team push | Auto-report from the SessionStart hook (piggybacks on pull) | The batch report waits at most 5 s; a timeout cancels neither the push nor the local acknowledgement after success |
| 6 | Health score formula | usage (0-60) + freshness (0-40) | The contributor dimension has little spread on small teams, so two dimensions suffice |
| 7 | Session content source | AI conversation and tool use (not git diff) | The point is to record where the AI used the wrong tool |
| 8 | Session filtering | Push only valuable sessions (tool errors / retries count as valuable) | Keeps the team repo free of noise |
| 9 | Hook tracking scope | Skill tool calls only | Tracking every tool produces a lot of noise; skill usage statistics are the core need |
| 10 | JSONL lifecycle | Truncate reported data only after every selected target confirms success | Failures keep the events (latest 5,000 at most); events added during a push wait for the next batch |
| 11 | Error handling | try-catch around every I/O operation + graceful degradation | No silent failures |
| 12 | Feature 3 push | Drop `push --stats`; auto-report only | Decision 5 already chose auto-reporting, so a manual command is redundant |
| 13 | Hook command | `teamai track`, a TypeScript CLI command | Type safety and input validation; sturdier than a bash one-liner |
| 14 | Direct git push | Reuse `pushRepoDirectly()` from `utils/git.ts` | DRY; no new git logic |

> Update (#484 / #485): neither reports nor learnings are pushed straight to the default branch any more. Reports go to `teamai-reports` and learnings to `teamai-learnings`, each pushed through the worktree of its orphan branch (`utils/branch-worktree.ts`). `pushRepoDirectly()` is now used only for the first repo creation during init and in CI.

## Accepted Features

### Core Features

#### 1. Session tool-usage records
**What:** Actively collect the AI conversation and tool-use record during a session, focusing on where the AI used the wrong tool. Triggered by `teamai session save` or by the Stop hook.

**How it works:**
```
Session in progress → the AI uses tools, converses
                    │
                    ▼
        user / AI runs teamai session save
                    │
                    ▼
        collect tool-use records + conversation summary
                    │
                    ▼
        assess value (tool misuse? retries? interesting finding?)
                    │
            ┌───────┴───────┐
            ▼               ▼
        valuable         not valuable
        mark pushable    keep locally only
            │
            ▼
    ~/.teamai/session-logs/<year-month>.md (append)
```

**Value evaluation rules (v1):**
- Valuable: contains tool errors, retries, rollbacks, AI self-corrections
- Valuable: a new pattern or creative solution was found
- Not valuable: pure chat, simple file operations, routine edits

**Storage:** `~/.teamai/session-logs/<year-month>.md`, aggregated by month.

The monthly file's read, full-session-ID deduplication and atomic replacement are serialized with a cross-process lock. A busy lock is retried for up to five seconds; a read failure preserves the existing log. Team summaries use the same transaction.

#### 2. Skill Usage Tracker (Local)
**What:** A PostToolUse hook detects Claude Code Skill tool calls and appends to the scope's `<dataHome>/usage.jsonl` (the configured project the session directory belongs to, otherwise user scope's `~/.teamai/user-usage.jsonl`; a directory without teamai configured records nothing, #748; a deleted directory keeps the scope the session last recorded, #810).

**Data format (JSONL, one event per line):**
```jsonl
{"skill":"code-review","timestamp":"2026-03-19T10:30:00Z","tool":"claude"}
{"skill":"tdd","timestamp":"2026-03-19T10:35:00Z","tool":"claude"}
```

**Aggregation:** `teamai stats` reads the JSONL and shows the aggregate.

**CLI output:**
```
Skill Usage Statistics:
  code-review    47 uses   last: 2h ago
  tdd            23 uses   last: yesterday
  plan-eng-review 5 uses   last: now
```

#### 3. Team Usage Aggregation
**What:** `teamai pull` aggregates the current scope's usage.jsonl into `stats/<user>.yaml`; a Git repo writes it to the separate `teamai-reports` branch (no MR).

**Push flow:**
```
teamai pull
    │
    ▼
aggregate the scope's usage file → stats/<user>.yaml
    │
    ▼
reports worktree → git add → git commit → git push (teamai-reports)
    │
    ├─ success → update the reported snapshot → clear this batch's events once every target succeeded
    └─ failure → keep local events and snapshot, restore the stats file from before aggregation
```

The 5-second limit wraps the whole report operation; after a timeout, pull carries on with its other work while the background operation still completes the push and local acknowledgement, then releases the related sync locks. A failed retry re-pushes the existing commit even when it rebuilds files identical to the previous commit, so no empty commit is needed.

Once every target is processed, pull truncates each active scope's usage file to the latest 5,000 entries (including HTTP and `usageReport: false` scopes, which never report, #788). Truncation must come after cleanup: cleanup deletes lines from the start of the file by the count the report read, and a truncation in between would shift that deletion onto unreported events. Hook appends, cleanup and truncation share one lock next to the usage file (`<usage file>.lock`); rewrites go through a temporary file and rename, preserving the original permissions. A hook that cannot take the lock within about 250 ms writes `*.pending-<id>.jsonl` (O_EXCL), merged by the next lock holder; a rewrite that cannot take the lock within about 5 seconds leaves the file alone. Pending files are no more permissive than the usage file (0600 when none exists yet). The workspace's `.teamai/.gitignore` ignores `usage.jsonl.*` and `usage.pending-*.jsonl`; existing files in single-repo mode are completed by `migrateSelfModeGitignoreContent`, and existing project-scope files by `ignoreUsageSideFiles` before a pending file is written or a rewrite happens.

This fix provides neither persistent batches nor remote de-duplication: a process killed between push and acknowledgement, or a retry after a partial multi-repo success, can still double-count. Waiting past the timeout neither cancels Git nor forces the process to exit.

### Expansion Features

#### 4. Skill Health Score
**What:** A simplified two-dimensional score = f(usage_frequency, last_used_freshness).

**Formula:**
- usage_score: normalized weekly usage count (0-60 points)
- freshness_score: days since last used, decaying (0-40 points)
- Total: 0-100, displayed as ★★★★★ (5 stars)
- contributor_count: shown for information only, not part of the score

#### 5. Team work-log aggregation
**What:** `teamai push --sessions` pushes valuable session summaries to `sessions/<user>/<year-month>.md` in the team repo. Direct commit, no MR.

**Retention:** Auto-cleanup of sessions older than 90 days.

#### 6. Skill Recommendations
**What:** After `teamai pull`, suggests skills that are popular with the team but the user hasn't tried yet.

**Output example:**
```
💡 Recommended skills (popular with your team):
  • code-review — used by 85% of team (you haven't tried it)
  • tdd — used by 70% of team
```

#### 7. Weekly Team Digest
**What:** `teamai digest` generates a formatted weekly summary of team activity.

**Output includes:**
- New/updated skills this week
- Most-used skills
- Session summary highlights (tool misuse patterns)
- Team activity stats

## Architecture

```
┌──────────────┐     ┌────────────────┐     ┌──────────────────┐
│ Claude Code  │     │  teamai CLI    │     │  Team Repo       │
│              │     │                │     │                  │
│ PostToolUse ─┼────▶│ usage-tracker  │     │ stats/<user>.yaml│
│ hook         │     │ → append JSONL │     │                  │
│              │     │                │     │ sessions/<user>/ │
│ In-session   │     │ session-       │     │  <year-month>.md │
│ session save─┼────▶│ collector.ts   │     │                  │
│ command      │     │                │     └──────────────────┘
└──────────────┘     │ health.ts      │            ▲
                     │ recommend.ts   │            │
┌──────────────┐     │ digest.ts      │     push --stats
│ Local        │     │ stats.ts       │     push --sessions
│ ~/.teamai/   │◀───│ team-push.ts ──┼────▶(direct commit, no MR)
│  usage*      │     │                │
│  sessions/   │     └────────────────┘
│   <Y-M>.md   │
└──────────────┘
```

\* Skill usage records are stored per scope: a project's in `<dataHome>/usage.jsonl` (the project partition), user scope's in `~/.teamai/user-usage.jsonl` (#748); `sessions/` stays machine-level under `~/.teamai/`.

## Security

- Usage data: skill name + timestamp only, no conversation content in JSONL
- Session summaries: AI tool-usage patterns, no concrete code or sensitive data
- Skill name validation (prevent path traversal)
- Sessions retention policy (90 days)
- JSONL: corrupted lines skipped gracefully on read

## NOT in Scope

- Contributor leaderboard — competitive ranking could hurt team culture
- Cross-team skill marketplace — needs cross-team authentication and authorization
- Real-time dashboards (web UI) — a CLI tool does not need a web front end
- Auto-generated skill README — low priority
- ML-based recommendations — simple frequency-based recommendations are enough
- Cursor PostToolUse hook — wait for Cursor's hook API to stabilize (TODO recorded)
